# UPLIFT — MAWSIM

**Demand-aware promo planning for Dubai retail.** Events, weather, holidays and school
calendars drive footfall; MAWSIM forecasts that demand per store zone, lets a bounded agent crew
plan promotions and creatives against the forecast, checks every claim against brand and food-
advertising rules with citations, and then measures **incremental lift** rather than clicks.

Built for SP Jain MAIB Term 4, AI 208 AI in Marketing. Owner: Krishna Mathur.

> ### The brand is fictional
> **SIDRA** (سدرة) is an invented Dubai speciality coffee and bakery chain with four locations.
> It is not a real company, and nothing here is a claim about any real business. The footfall and
> point-of-sale figures it is planned against are **simulated**, generated by a seeded model in
> `pipeline/footfall.py`, and every row, API response and chart that carries them says so. A real
> pilot would replace them with an actual POS export; nothing else in the system would change.

## Standing constraints

- **Zero paid inference.** Ollama (local) → Gemini free tier → Groq free tier → a deterministic
  stub. Anthropic is present in the provider chain and permanently refuses to serve, so the
  refusal is visible in the code and covered by a test rather than being an absence someone later
  "fixes". Budgets are counted in **requests**, never tokens.
- **Only free, licensed data.** Every source is recorded in [`docs/datasets.md`](docs/datasets.md)
  with its URL, the date it was verified by running it, and its licence. Where a source turned
  out to be unusable, the fallback actually in use is named there and the reason is given.
- **Every number traces to [`docs/results/`](docs/results).** No figure in any document is typed
  by hand.
- **No agent has a side-effect tool.** Nothing is published or executed externally. Exporting a
  campaign is a human action, taken outside this application.

## Running it

```bash
uv sync --extra dev          # Python side
cd apps/web && npm install   # web side
make check                   # the green bar: lint, tests, contrast, placeholders, typecheck
make api                     # http://localhost:8000/docs
make web                     # http://localhost:3000
```

## Layout

| Path | What lives there |
|---|---|
| `services/api/` | FastAPI service: provider chains, RAG, marketing models, the crew |
| `pipeline/` | The four ETLs — weather, calendar, events, footfall — each with `--verify` |
| `apps/web/` | Next 16 web application, 15 tabs, and the 3D season view |
| `data/brand/sidra.yaml` | The single source of truth for the fictional brand |
| `docs/results/` | Every measured number, written by a script, referenced by every document |
| `docs/datasets.md` · `docs/models.md` | What the data is, what the models are, and why |

## Not advice

MAWSIM produces a marketing plan and a compliance opinion for a fictional brand as coursework.
It is not legal advice, not regulatory clearance, and not a substitute for real customer
research. Its persona panel simulates reactions; it does not observe them.
